## 1. ゲーム概要

**ゲーム名**：時価総額チキンレース

日本の上場企業を選んでいき、合計時価総額が目標金額に最も近づいたプレイヤーが勝ち。**時価総額は常に非表示**で、会社名だけを手がかりに規模を推測するのがゲームの本質。目標金額を超えるとドボン（失格）になるが、**ドボンはゲーム中には分からず結果画面を開いて初めて発覚する**のがスリルのポイント。

### 難易度

| 難易度 | 目標金額 |
|--------|---------|
| Easy   | 100兆円 |
| Normal | 50兆円  |
| Hard   | 10兆円  |

## 3. ゲームルール

### 1人プレイ

- 100社の企業リストから自由に選択（銘柄コード順・2列グリッド）
- 制限時間：5分
- 合計金額は非表示。「自分のリスト」から仮計算入力欄に予想値を手入力して推測する
- 選択の取り消し不可・選択済み企業はグレーアウトして残す

| 終了条件 | 挙動 |
|----------|------|
| 5分経過 | 強制終了→結果画面へ |
| STOPボタン押下 | 確認ダイアログ→「やめる」で結果画面へ |
| 全企業選択 | 自動で結果画面へ |

### 2人対戦（ターン制）

- 同じ100社リストを見ながら**交互に1社ずつ選択**
- 先攻・後攻はゲーム開始時にランダム決定
- 1ターン＝1分。選択したら即ターン交代。1分経過でパス（自動ターン交代）
- 合計金額は非表示。選択の取り消し不可

#### マッチング
- URL共有またはQRコードで入室
- 難易度はホストが選択（変更不可）
- ゲスト入室後にホストが開始ボタンを押してスタート

#### 終了条件

| 終了条件 | 挙動 |
|----------|------|
| STOPボタン押下 | 確認ダイアログ→「やめる」で決定。相手に2分の猶予が発生 |
| 2分以内に相手がSTOP | 両者の答え合わせへ |
| 2分経過 | 強制終了→答え合わせへ |
| 相手が切断 | 勝敗なし・自分の結果のみ表示 |

> STOPダイアログの「相手にはまだ2分間の猶予が発生します」という補足文言は、**相手がすでにSTOP済みの場合は表示しない**。

#### 再戦
- どちらかが「もう一度」を押したら再戦スタート
- **ホストが押した場合**：即座に企業リストを新規抽出してゲームを自動スタート
- **ゲストが押した場合**：ホストの「もう一度」ボタンが緑色の「相手が再戦を希望しています！開始する」に変化。ホストが押すと自動スタート
- 再戦時は企業リストを毎回新規抽出
- ルーム有効期限：1〜2時間（URLの共有し直し不要）

### 勝敗判定（2人対戦）

| 状況 | 判定 |
|------|------|
| 差額が近い方 | 勝ち |
| 差額が完全に同じ | 引き分け |
| 両者ともドボン | 引き分け（将来変更の可能性あり） |
| 片方のみドボン | ドボンしていない方の勝ち |

### Firebase データ構造

```
rooms/{roomId}/
├── status            # "waiting" | "playing" | "finished"
├── difficulty        # "easy" | "normal" | "hard"
├── retryRequested    # ゲストが再戦希望を出したフラグ
├── companies/{code}/ # name・oku・cho
├── turn/
│   ├── current       # "host" | "guest"
│   └── startedAt
├── players/
│   ├── host/         # uid・connected・stopped・stoppedAt・selections/{code}: timestamp
│   └── guest/        # 同上
└── timer/            # startedAt・triggerStopAt・deadlineAt
```

> `selections/{code}` の値は `true` ではなく **ServerValue.TIMESTAMP** で保存し、タイムスタンプ昇順でソートすることで選択順を復元する。

### 実装上の注意点

**Firebase関連**
- `roomRef` は `useRef(db.ref(...)).current` でレンダーをまたいで同じ参照を使い回す
- Firebase のリスナーは各 `useEffect` の return で必ず `.off()` を呼ぶ
- `status` の購読は VsGameScreen 内ではゲスト専用。ホストは `handleGameEnd()` で直接 `status:"finished"` を書き込む
- `handleGameEnd` はホストのみ実行（競合防止）。`gameEndedRef`（useRef）で二重呼び出しを防止

**再戦フロー**
- `guestwait` 監視（App レベル）は `status:"finished"` を受け取った場合は無視する（カウントダウンバグ防止）
- `vsresult` 監視（App レベル）は `finishedSeen` フラグで「finished を見てから playing になった」場合のみ再戦と判定する
- `setGameKey` はホスト側は `startVsGame()` で、ゲスト側は `guestwait` 監視で行う（二重インクリメント防止）

**その他**
- `fmt()` 関数：`addComma(triVal.toFixed(2))` は小数点をカンマと誤認するためNG。`toFixed(2)` → 小数点で分割 → 整数部分のみカンマ → 結合する
- Firebase設定（`firebaseConfig`）はBabel外の `<script>` タグに直書き
- ゲスト入室：URLパラメータ `?room={roomId}` を検出して自動入室
- 切断検知：`myConRef.onDisconnect().set(false)` で登録
