# 時価総額ゲーム｜企画・要件定義書 v8.0

> ステータス：1人プレイUI実装済み・動作確認中。次フェーズは2人対戦（Firebase）。

---

## 1. ゲーム概要

### コンセプト
日本の上場企業を選んでいき、合計時価総額が目標金額に最も近づいたプレイヤーが勝ち。  
**時価総額は常に非表示**。会社名だけを手がかりに規模を推測するのがゲームの本質。  
「超えたら失格（1人プレイ）」のスリルを持つ、**オリジナルルールのチキンレースゲーム**。

### ゲーム名
**時価総額チキンレース**（確定）

---

## 2. 難易度設定（3段階）

| 難易度 | 目標金額 | ヒント |
|--------|----------|--------|
| Easy | 100兆円 | なし |
| Normal | 50兆円 | なし |
| Hard | 10兆円 | なし |

> ※ヒント（業種表示など）は実装しない。目標金額の差のみで難易度を表現する。  
> ※目標金額が低いほど難しく、ドボン（即失格）のリスクが高まる。

---

## 3. 企業リストの構成

- 元データ：約4,000社（日本の上場企業）
- ゲーム開始時に約100社にランダム抽出して使用
- 抽出ロジック：難易度によらず同一（将来的に規模帯を難易度別に調整予定）
- 持株会社は混入させない
- 検索・絞り込み機能はなし

---

## 4. ゲームルール・終了条件

### 1人プレイ

- 表示された企業リスト（約100社）から自由に選択
- 制限時間：**5分**
- 企業リスト表示：**銘柄コード順・2列グリッド・会社名省略（末尾…）**
- 選択済み企業：**グレーアウトして残す**
- 選択済みリスト表示：**銘柄コード＋会社名**
- 合計金額：**非表示**
- 選択の取り消し：**不可**

| 終了条件 | 挙動 |
|----------|------|
| 5分経過 | 強制終了→結果表示 |
| 目標金額超過（ドボン） | ゲーム画面上で「ドボン！」表示→結果画面へ遷移 |
| ストップボタン押下 | 確認ダイアログ→「はい」で終了→結果表示 |
| 全企業選択 | そのまま結果表示 |

### 2人対戦

- 同じ企業リスト（約100社）を見ながら**同時進行で自由に選択**（ターン制ではない）
- 同じ企業は**早い者勝ち**（両者が同時に選べない）
- 失格なし（目標金額を超えても続行可能）
- 合計金額：**非表示**
- 選択の取り消し：**不可**

#### マッチング方法
- URLまたはQRコードを共有してルームに入室
- 難易度：**ルーム作成者が選択**（待機画面からの変更不可）
- ゲーム開始：**ホストが開始ボタンを押す**（相手入室後に有効化）
- 相手の選択：**ボタンで切り替えてリアルタイム確認可能**

#### 終了条件

| 終了条件 | 挙動 |
|----------|------|
| 片方がストップボタン押下 | 確認ダイアログ→「はい」で決定。もう片方に**2分の制限時間**が発生、押した側は自分のリストと相手画面を切り替えて見守れる |
| 2分以内にもう片方がストップ | 両者の答え合わせへ |
| 2分経過（時間切れ） | 強制終了→答え合わせへ |
| 相手が切断 | 「相手が切断しました」と表示→ゲーム終了→結果画面へ（勝敗なし・自分の選択のみ開示） |

#### 再戦
- 結果画面に「もう一度」ボタンを設置
- 同じルームIDでゲーム状態をリセットして再戦可能（URLの共有し直し不要）
- ルームの有効期限：**1〜2時間**
- 再戦時のリセット：同じroomIdのデータを上書き初期化

### 勝敗判定（2人対戦）

| 状況 | 判定 |
|------|------|
| 差額が近い方 | 勝ち |
| 差額が完全に同じ | 引き分け |
| 両者ともドボン | 引き分け（将来的に変更の可能性あり） |
| 片方のみドボン | ドボンしていない方の勝ち |

#### 画面③ ゲーム画面（1人プレイ）

**表示要素**

1. 企業をタップした瞬間に合計が目標金額を超過
2. ゲーム画面上に「ドボン！」を表示
3. 結果画面（`/result`）へ遷移

**タイムアップ時の挙動**
- 残り0秒で自動的に結果画面へ遷移

#### 画面⑥ ゲーム画面（2人対戦）

**表示要素**
- 目標金額

- 企業リスト（2列グリッド・銘柄コード順・選択済みはグレーアウト）
- 自分の選択済みリスト（銘柄コード＋会社名）
- 「相手のリストを見る」ボタン（押すと相手のリストをリアルタイム表示、切り替え式）

- ※合計金額は非表示

**ボタン動作**
- 企業タップ→早い者勝ちでFirebaseに書き込み（相手が選択済みなら選択不可・グレーアウト）
- ストップボタン→確認ダイアログ「本当にストップしますか？」→「はい」でFirebaseに書き込み

**切断時の挙動**
- 相手の `connected` が false になった瞬間に「相手が切断しました」を表示

**ボタン**

## 6. データ設計

### CSVの構成

#### 元データ（生CSV）

| 列名 | 内容 |
|------|------|
| コード | 銘柄コード（アルファベット混じりあり） |
| 銘柄名 | 会社名 |
| 市場 | 上場市場（東Pなど） |
| 現在値 | 株価 |
| 前日比(%) | 騰落率 |
| 時価総額(百万円) | 時価総額 |

#### 加工済みCSV（ゲームで使用）

| 列名 | 内容 |
|------|------|
| code | 銘柄コード |
| name | 会社名 |
| market_cap | 時価総額（百万円） |

> ※「市場」「現在値」「前日比」はゲームでは使用しないため除外。

#### 加工スクリプト
- Python製の自動化スクリプトで生CSV→加工済みCSVを生成
- 月次更新のたびに実行して差し替える運用

### データ更新フロー

| フェーズ | 方法 |
|----------|------|
| 初期〜当面 | 月1回手動でCSVを差し替え |
| 将来 | J-Quants API（日本取引所グループ公式）で前日終値を毎日18時に自動更新 |

### 基準日の表示
- ゲーム画面・結果画面に時価総額の基準日を表示する（例：「2025年4月末時点」）

## 7. Firebase設計

### 基本方針
- 1人プレイはFirebase不要（フロントエンドのみで完結）
- 2人対戦のリアルタイム同期にのみFirebase Realtime Databaseを使用
- プレイヤー識別はFirebase Anonymous認証を使用

### データ構造

```
rooms/
└── {roomId}/
    ├── status          # "waiting" | "playing" | "finished"
    ├── difficulty      # "easy" | "normal" | "hard"
    ├── targetAmount    # 100 | 50 | 10（兆円）
    ├── createdAt       # タイムスタンプ
    ├── expiresAt       # タイムスタンプ（createdAtから1〜2時間後）
    ├── companies/      # ホストが抽出した約100社
    │   └── {code}/
    │       ├── name        # 会社名
    │       └── marketCap   # 時価総額（百万円）
    ├── players/
    │   ├── host/
    │   │   ├── uid             # Firebase Anonymous UID
    │   │   ├── connected       # true | false（切断検知用）
    │   │   ├── stopped         # true | false（ストップボタン）
    │   │   ├── stoppedAt       # タイムスタンプ（ストップした時刻）
    │   │   └── selections/     # 選択済み企業（早い者勝ち）
    │   │       └── {code}: true
    │   └── guest/
    │       ├── uid
    │       ├── connected
    │       ├── stopped
    │       ├── stoppedAt
    │       └── selections/
    │           └── {code}: true
    └── timer/
        ├── startedAt       # ゲーム開始タイムスタンプ
        ├── triggerStopAt   # 片方がストップした時刻
        └── deadlineAt      # 残り2分の期限タイムスタンプ
```

### 設計のポイント

#### selections を `{code}: true` にする理由
企業ごとにフラットなキーで持つことで（例：`{ "7203": true, "9984": true }`）、Firebaseのリアルタイム更新と相性が良く、早い者勝ち判定もシンプルに実装できる。

#### 切断検知（connected フラグ）
Firebase の `onDisconnect()` を使用。接続時に「切断されたら `connected: false` にする」命令をあらかじめ登録しておくことで、ブラウザが突然閉じられた場合も自動検知できる。

#### timer を独立させる理由
ストップ関連の時刻情報を1箇所にまとめることで、「片方がストップ→相手に2分タイマー発生」のロジックを一元管理できる。

#### 再戦時のリセット
「もう一度」ボタン押下時、同じroomIdのデータ（companies・selections・timer・status等）を上書き初期化して再利用する。URLの共有し直しは不要。

## 8. 状態管理設計

### 方針
- **useContext + useReducer** を使用（外部ライブラリなし）
- 1人プレイ・2人対戦の状態を **1つのGameContextにまとめる**

### 画面とURLの対応

| URL | 画面 |
|-----|------|
| `/` | トップ画面 |
| `/select-mode` | 難易度選択（1人プレイ） |
| `/game` | ゲーム画面（1人プレイ） |
| `/result` | 結果画面（1人プレイ） |
| `/room/create` | ルーム作成・難易度選択（2人対戦） |
| `/room/:roomId` | ルーム待機画面 |
| `/room/:roomId/game` | ゲーム画面（2人対戦） |
| `/room/:roomId/result` | 結果画面（2人対戦） |

### GameContextの構造

```javascript
GameContext
├── 設定系
│   ├── difficulty        // "easy" | "normal" | "hard"
│   ├── targetAmount      // 100 | 50 | 10（兆円）
│   ├── companies         // 使用する100社リスト
│   └── dataUpdatedAt     // 基準日
│
├── 1人プレイ系
│   ├── selections        // 選択済み企業コードのSet
│   ├── status            // "idle" | "playing" | "stopped" | "failed" | "finished"
│   └── timeLeft          // 残り秒数（300秒スタート）
│
└── 2人対戦系
    ├── roomId            // ルームID
    ├── role              // "host" | "guest"
    ├── mySelections      // 自分の選択済み企業コードのSet
    ├── opponentSelections // 相手の選択済み企業コードのSet（Firebaseから購読）
    ├── myUid             // Firebase Anonymous UID
    ├── roomStatus        // "waiting" | "playing" | "finished"
    ├── stopState         // 誰がストップしたか
    └── timeLeft          // 残り秒数（ストップ後の2分）
```
